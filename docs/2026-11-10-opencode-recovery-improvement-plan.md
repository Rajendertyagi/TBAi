## Part D — Target architecture

### D.1 Principles (post-adoption, evidence-gated)

- **Library/SDK-first, but invariant-first:** use official OpenCode SDK operations and existing dependencies where behavior is proven equivalent; keep TBAi adapters thin.
- **No framework/dependency multiplication:** no second SSE/state/cache/retry system unless clearly superior and justified; prefer existing Zustand/Zod/native APIs/SDK.
- **TBAi remains authoritative for app policy/state:** application persistence, conversation/session binding, scheduler orchestration, adopted-vs-managed ownership, supervision, recovery, workspace resolution, configuration redaction and write policy, and app-specific UX/state.
- **OpenCode remains authoritative for runtime execution state:** runtime execution, sessions, messages, events, providers, models, agents, and supported server APIs.
- **Safety boundaries preserved:** origin-bound credentials/transport, redirect refusal, proxy allowlist/authz/scope, fail-closed ownership/lease checks, no non-owned lifecycle control, no plaintext secrets.
- **Conditional improvements only:** proposed simplifications/caches are not settled architecture until evidence supports them.

### D.3 Intended simplifications (only if proven)

- **Config read fetch path (LIB-OPP-02):** possible thin wrapper over `client.config.get()` while retaining TBAI document discovery/redaction/write-policy logic.
- **Capabilities frontend (LIB-OPP-05):** possible shared store/cache (Zustand pattern reuse) replacing per-mount duplicate fetches, preserving recovery/loading/error semantics. **Unproven; not a settled architectural decision.**
- **SSE diagnostics (LIB-OPP-01):** possible `eventsource-parser` side-channel observer only if byte forwarding/metrics/cancellation remain equivalent.
- **Readiness probe (LIB-OPP-03):** retain custom gate unless SDK-based probe proves identical semantics with less complexity (including explicit `redirect: "manual"` non-200 refusal behavior).
- **JSONC (LIB-OPP-04):** no write-path migration without proven comment-preserving safe edits; read-only tolerance only if clearly beneficial.
- **Config store:** no shared config store established as necessary; preserve existing working patterns unless evidence supports a change.
